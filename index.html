2. 系统边界

两套前端、一套云端数据。标注端是唯一写入口（题库）；网页端只读题库 + 写组卷/建议。

图 1 · 双端边界：标注端写题库，网页端消费题库并写组卷

标注端（改造现有）

  • 继续用 SQLite + 本地文件干活
  • 新增「同步到云端」：元数据 upsert + 题图上传 R2
  • 暂不做「从云端拉同事数据」
  • 路径字段逐步改成 R2 key（本地仍存本地路径）

云端（新建）

  • Supabase：Auth（邮箱密码）+ Postgres
  • R2：题目/答案裁剪图 + 导出 PDF
  • 导出 Worker：拉 R2 题图 → 拼 PDF → 写回 R2
  • CF Workers：R2 公开读缓存加速

网页端（新建）

  • 登录后筛题、看题图、收藏筛选
  • 组卷（私有/共享）+ 随机抽题
  • 触发服务端导出、下载 PDF
  • 对题目提交 suggestion

3. 存储策略（省空间）

原则：网页只要题目裁剪图，所以 R2 只存裁剪图和导出产物。切页图与原 PDF 留在标注机本地。

资产本地标注机云端 R2说明
原 PDF 保留 不传 网页端用不到
切页图 pages/* 保留 不传 框选/OCR 依赖；网页无上下文需求
题目裁剪图 保留 全量上传 question_boxes.image
答案裁剪图 保留 全量上传 导出带答案时需要
导出 PDF 按需下载 任务产物 可设 7 天过期
元数据 SQLite Postgres 同步时以云端为「已发布」真相

本地 SQLite 缓存边界（量大之后）

规则：元数据（题目、框、标签、组卷引用）全量留本地；题图文件不搞「云端全量镜像回本地」。

MVP 单管理员时本地本来就有全部图，无需回拉。将来多管理员/换机时：本地只缓存最近编辑的题目图 + 可选 LRU，其余需要时从 R2 签 URL 读。表里存 image_key，不存绝对路径。

R2 Key 约定

papers/{paper_id}/q{question_id}_{box_id}.webp      -- 按试卷分文件夹
papers/{ms_paper_id}/a{answer_id}_{box_id}.webp      -- 答案图按 MS 卷归档
exports/{job_id}/paper.pdf
exports/{job_id}/meta.json

R2 是扁平对象存储，"文件夹"只是 key 前缀，没有目录数量限制；按试卷分组便于浏览与清理。不按模块（section）分组：一题可多标签且会改标签，会导致 key 频繁变动重传。

4. 同步协议（手动推送）

标注端点「同步到云端」后执行一次幂等推送。失败可重跑；以 updated_at 做脏检查。

图 2 · 同步流水线：可重入、按 updated_at / hash 增量

不回传：同事的组卷、suggestion、收藏不写回标注端本地库。网页是消费端；标注员在 Supabase 后台/网页 admin 页看 suggestion 即可。

5. 表结构草稿（Postgres / Supabase）

在现有 SQLite 模型上增量：加用户、权限、建议、组卷可见性；路径列改 key。

-- ===== 身份与权限 =====
profiles (
  id uuid primary key references auth.users,
  email text unique not null,
  role text not null default 'teacher',   -- 'admin' | 'teacher'
  can_see_drafts boolean default false,   -- 未校对题是否可见
  created_at timestamptz default now()
);

-- 题目可见性授予：不写行 = 按角色默认策略
question_grants (
  id bigserial primary key,
  user_id uuid references profiles(id) on delete cascade,
  scope text not null,          -- 'section' | 'paper' | 'question'
  scope_value text not null,    -- 模块名 / paper_id / question_id
  created_at timestamptz default now(),
  unique (user_id, scope, scope_value)
);

-- ===== 题库（与现 SQLite 对齐，路径改 key）=====
papers (
  id bigint primary key,        -- 同步保留原 id，或用 uuid 重映射
  filename text, exam_code text,
  year_token text, season_token text,
  is_answer boolean default false,
  paired_paper_id bigint,
  page_count int,
  source_updated_at timestamptz,
  deleted_at timestamptz        -- 软删
);

questions (
  id bigint primary key,
  paper_id bigint references papers(id),
  question_no text, section text,
  status text default 'draft',  -- 'draft' | 'confirmed'
  notes text, is_favorite boolean default false,
  updated_at timestamptz
);

question_boxes (
  id bigint primary key,
  question_id bigint references questions(id) on delete cascade,
  paper_id bigint, page int,
  bbox jsonb not null,
  image_key text not null,      -- R2 key，不再存绝对路径
  created_at timestamptz
);

answers (
  id bigint primary key,
  question_id bigint unique references questions(id),
  ms_paper_id bigint references papers(id),
  notes text, updated_at timestamptz
);

answer_boxes (
  id bigint primary key,
  answer_id bigint references answers(id) on delete cascade,
  ms_paper_id bigint, page int,
  bbox jsonb not null, image_key text not null
);

section_defs (id, name unique, content, color, updated_at);
section_groups (id, name unique, show_in_filter, updated_at);
section_group_members (group_id, section_name);
question_sections (question_id, section_name, unique(question_id, section_name));

-- ===== 组卷 =====
compositions (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  title text, header_text text, footer_text text, cover_lines text,
  include_answers boolean default false,
  answers_placement text default 'end',
  group_by_section boolean default true,
  show_section_headers boolean default true,
  show_question_info boolean default true,
  show_page_numbers boolean default true,
  owner_id uuid references profiles(id),
  visibility text default 'private',  -- 'private' | 'shared'
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

composition_items (
  id bigserial primary key,
  composition_id uuid references compositions(id) on delete cascade,
  question_id bigint references questions(id),
  sort_order int not null,
  item_type text default 'question',   -- 'question' | 'blank'
  blank_pages int default 0,
  score float, custom_header text,
  unique (composition_id, question_id)
);

-- ===== 建议 =====
suggestions (
  id bigserial primary key,
  question_id bigint references questions(id) on delete cascade,
  user_id uuid references profiles(id),
  body text not null,
  status text default 'open',          -- 'open' | 'accepted' | 'rejected'
  created_at timestamptz default now()
);

-- ===== 同步审计 =====
sync_log (
  id bigserial primary key,
  entity text, entity_id text,
  action text, payload_hash text,
  created_at timestamptz default now()
);

id 策略建议：云端 papers/questions 继续用整数 id（同步时一一对应），组卷/用户用 uuid。若担心碰撞，同步可带 source='desktop-001' 前缀，MVP 不必。

6. 权限模型（MVP 可糙）

第一版目标是你自己内部测通，策略简单可解释；RLS 先写规则，不够再加。

admin（你）

  • 题库读写（经同步，不在网页改题）
  • 可见全部，含 draft
  • 管理 profiles / grants
  • 处理 suggestion
  • 可看所有组卷

teacher（同事）

  • 题库只读
  • 默认见 confirmed 题
  • 可被 grant 额外 section/paper/question
  • 组卷：自己的 private + 标为 shared 的
  • 可提 suggestion、导出

可见性判定（伪代码）

def can_see(user, q):
  if user.role == 'admin': return True
  if q.status != 'confirmed' and not user.can_see_drafts: return False
  if has_grant(user, 'question', q.id): return True
  if has_grant(user, 'paper', q.paper_id): return True
  if has_grant(user, 'section', q.section): return True
  # 未配置任何 grant 的用户：见全部 confirmed（内测默认）
  return not user_has_any_grant(user) or False_policy

内测默认：teacher 无 grant 行时可见全部 confirmed 题——先让人跑通。要收紧时，改成「无 grant 则全不可见」，并配管理界面批量授予 section。

隐藏未校对：与上述同一开关（can_see_drafts + status 过滤），不单做一套。

7. MVP 功能清单

必须有

  • 邮箱密码登录 Supabase Auth；注册可先关闭，由 admin 邀请/建号
  • 题库浏览 按模块/试卷/年份/季节筛选；列表只出裁剪图；题号跳转
  • 组卷 建卷、加题、排序、插入空白页、私有/共享；复用现有 composition 字段
  • 随机抽题 按 section 数量抽题进当前卷
  • 服务端导出 PDF Worker 从 R2 取题图拼卷（可含答案）；浏览器下载
  • 标注端同步 脏数据扫描 → Postgres upsert → R2 传图
  • suggestion 对题提意见；admin 在简单列表里接受/忽略

明确不做（本版）

  • 实时同步 / 云端改题 题库写入口只在标注端
  • 原卷上下文 / 切页图 不上 R2，网页不展示
  • 多管理员协同标注 单管理员 + TODO
  • 组卷版本冻结 题目更新后卷面跟着变；TODO 加开关
  • 企业微信 SSO 先邮箱密码
  • 复杂审计/配额 sync_log 有即可

9. 实施顺序

0

云上底座

建 Supabase 项目 → profiles/Auth → 迁移表结构 → 建 R2 bucket + Workers 缓存。用假数据打通读写。

1

标注端同步

路径改 image_key、写 sync 命令（元数据 upsert + R2 传图 + sync_log）。你自己先把现有题库推上去。

2

网页端骨架

登录 → 题库筛选/预览 → 最简组卷（增删排序、私有/共享）。此时已可给同事「看题 + 搭卷」。

3

随机抽题 + 导出

移植 random_pick；导出 Worker 从 R2 取图拼 PDF；网页下载。MVP 功能闭环。

4

权限与建议收尾

grants 生效、draft 开关、suggestion 列表。内测反馈后再开注册/加同事。

建议第一个可交付里程碑：Phase 1 完成后，你应能在 Supabase 表里看到现有题库，在 R2 里看到裁剪图。这一条通了，网页端就是纯消费，风险最低。
